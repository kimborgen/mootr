# Go review recipes

The finds that keep coming back in reviews of Go ports and in the developer work around them. Check your change against the matching section before you ask for review. Each entry cites the retro item it came from (`S-` key); the item has the full thread.

## Go concurrency

- **S-2878** (12 +1s): TS checks a value and sets it with no `await` between, so nothing runs in the gap. Go's per-request goroutines do run in that gap. Check: for every check-then-act in the TS source, look for a SQLite or lock call between the check and the set. Shown by: PR #912 (S-2848), where two compact requests could start two compactors. Fixed in 57aab6cb with a slot reserved under the lock and a compare-and-clear UPDATE.
- **S-4093** (the procedure for S-2878): when a TS daemon function ports to Go, list every read that feeds a later separate DB write. Check each read against the concurrent writers, since a read and its write in separate transactions can interleave with a move or a delete. Shown by: PR #1275, where each invariant passed alone and a concurrent `MoveToSuccessor` could still interleave (round 1 approve became request_changes, r7fbf42).
- **S-2857**: a route behind a client-id dedup must not run on `r.Context()`. A hang-up after a commit cancels the later writes, the dedup forgets the id, and the retry stores a second copy. Use `context.WithoutCancel` for the writes. Shown by: `TestSendSurvivesDisconnect` (PR #908, fixed in fe67ad5).
- **S-3524**: startup cleanup can remove an older running daemon's active temp files before the new process fails its port bind. Trace the sweep before bind exclusion. An mtime cutoff only mitigates this, since a paused writer can outlive it. Shown by: PR #1111, where both reviewers requested changes at 8f6df573.
- **S-4091**: undo only what this call provably made. "Missing before" is not proof under concurrency. Check that a rollback step deletes a path or branch only when this call created it. Shown by: S-4084, where a concurrent same-name spawn's live worktree could be force-removed. Fix: reserve the name under one lock, and after a failed add only prune and report.

## Port parity

- **S-3775**: test the Go text and ranking against the TS source with a small `.mjs` reference that imports `src/`. Feed it tricky inputs: UTF-16 slicing, JS `\s`, Unicode, long text. Shown by: the search parity reference (S-3735), which matched on the first run because the port copied the JS semantics up front.
- **S-4060**: port each tool with a `both()` harness. It runs the same calls through the TS and Go sides against one stub and compares results and raw bodies. Check: a Go route that shares a path with an existing route. Route by the query, and place the new route first. Shown by: `TestAgentToolsMatchTS` (S-4057), 23 calls.
- **S-2681**: read the TS value builder, not only its defaults. Check the order of fallback keys: TS `homeOf(user)` puts `home` first, and a test that sets only one key can't see the order. Shown by: PR #857, request_changes at 1b867715.
- **S-4065**: cover missing values and the source language's numeric forms when porting CLI coercion: binary, octal and hex, and a missing value. TS `Number(undefined)` rejects it. Shown by: PR #1264, where a dropped `strings.Cut` found flag turned a missing value into zero.
- **S-4056**: when a nightly parity test newly fails, run it on main, then in a detached worktree at the nightly sha, before you bisect. Shown by: S-4055, where the nightly reproduced in about 10 s, and a TS contract change whose Go port merged after the nightly saved bisecting 33 merges.
- **S-4077**: seed a home through the TS APIs, run `PRAGMA wal_checkpoint(TRUNCATE)`, then copy `stam.db`. Without the checkpoint the copy has no tables. Go and TS output must then match byte for byte over the same file. Shown by: the digest parity reference (S-4059, S-4063, S-4069), where nine mutations were each caught.
- **S-4088**: a deterministic hung git fetch needs no network: `GIT_SSH_COMMAND="sleep 30; :"` with an `ssh://` remote. The trailing `; :` swallows the host and command arguments git appends; plain `sleep 30` exits at once. Shown by: `TestCreateWorktreeFetchTimeout` (S-4084), which runs in well under a second.
- **S-4090**: when a function defines an undo closure, list every error return after the resource exists and check that each one calls it. A linear scan of the `return` lines finds the gap in a minute. Shown by: PR #1274, where `spawnWrite` called `dropTree` on five of six failure paths, and the `SetShared` path leaked the worktree.
- **S-3997**: before you decide a parity question, grep the TS original. Check how TS does the same step, and whether it has the same pattern. Shown by: PR #1246, where TS ran four home reads in parallel and Go ran them in order. The grep separated a parity regression from a pattern TS already had.
- **S-4012**: when a decoder tightens, grep the writers too. They may still store values the decoder now treats as hostile. Shown by: PR #1253 (S-4003), where TS and Go writers of `visibility` still accepted arrays, and those arrays now silently close the agent.

- **S-4101**: when rows from several sources merge into one list, check how readers key the merged list, not only where the rows are stored. Check a colliding id in both sources. Shown by: PR #1276, where `GET /api/agents` returned both rows and a Map keyed by id let the peer row replace the local one.
- **S-4040** (test recipe): write one parity test with shared send steps, run through the TS reference and the Go daemon, and compare the results and the tables. Shown by: `TestSendMatchesTS` with the replies-only steps (S-4018), which exposed the forward-target delivery bug in both daemons.

## Security sanitizer review

- **S-4026**: redact only tokens of 8 or more characters. Substring redaction of a short dummy token rewrites ordinary words. Shown by: `go/check.sh` `TestHandOffSwitchedItsas` (S-3994), where a one-letter token turned "switched agent" into a redacted string. Only `go/check.sh` caught it.
- **S-4027**: before a change mutates a caught error (`e.message = …`), check in node whether that error type allows it. `fetch`'s `DOMException` does not, so the assignment throws in strict ESM. Shown by: PR #1257 (S-3994), where every peer timeout lost its name and text, and the tests never reached the catch.
- **S-4037**: when a piped stream becomes a buffered read, check its size cap, its deadline, and which try/catch now covers it. Shown by: PR #1257, where refusal bodies were read with no cap, under a headers-only timer, so a slow refusal marked a live peer down.
- **S-4045**: probe each helper's own limits: recursion depth, `inspect`'s string and array caps, and any catch that falls back after parsing succeeds, including recursive sanitization failures. Shown by: PR #1257 at ee899f10, where deep JSON overflowed `redactDeep`, and `inspect` cut strings at 10k characters, which hid a token in `cause.input`.
- **S-4046**: review sanitizers for lossy inspection, and for an exception that restores the original input. Check the actual properties, and fail closed once parsing succeeds. Shown by: PR #1257, round 2, where all of the ring requested changes.
- **S-4048**: a fail-closed check that treats a throwing getter as unsafe must not re-read the same fields unguarded afterwards. Keep every read after the check inside the try, `Reflect.ownKeys` included. Shown by: PR #1257 at f9b29a87, where `e.message`, `e.name` and `e.cause.code` were re-read after a getter threw.

## Developer recipes

- **S-4098**: before coding a ported parse rule, write its edge table: one row per edge (empty input, the cap hit, a partial line, trailing space), each with its expected output. Shown by: S-4085, the workspace script's last-line parse. It took four review rounds of single-edge fixes, and the table would have saved three.
- **S-3907** (mutation-check recipe, the C item of that proposal): commit before you mutate. Script the mutations. Run each with `timeout` and `--test-name-pattern`, one variant per guard.
- **S-4006** (extends the recipe above): mutate the whole check, not only its gate. Removing only `if (!replied.delete(id)) return;` in `raiseAsk` left the slow-path test green. Removing the whole check failed it as expected (S-3980).
- **S-2989**: a synchronous JS cache rebuild that sets nil and then rebuilds leaves a cold window in Go. Build the new index first, then swap it in under a generation counter. Shown by: PR #952 (S-2952), fixed in 9287e42.
- **S-3234**: a hook that fires right before a per-agent lock blocks gives a race test a deterministic "queued" signal, with no sleep. Trap: a test that holds the serial lock and calls `Shutdown` on the same goroutine deadlocks, so run the stop on its own goroutine and wait for its ack. Shown by: #1017/B4b, recheck approved at b793fabd.
- **S-3957**: trace worker completion and cache invalidation apart from the caller's timeout response. The caller's timeout does not stop the worker. Shown by: PR #1236 at 167e95a, where `Embed` could not be cancelled and `WarmLessons` committed after a concurrent `ForgetLessons`.
- **S-3965**: give overlapping operations separate release gates, and await the newer completion before you release the stale one. Without the generation guard, a test of two overlapping warms can pass with the older worker committing first. Shown by: PR #1236 at 62faa4187, `lessons_test.go`.
- **S-3970**: probe a mutex with `TryLock` before you start the competing goroutines. A warm's ticket lock can look like the caller holding the mutex. Shown by: PR #1236 at c6bb3656.
- **S-3971**: a Go parity test against live TS code must run uncached. `go test -count=1` in `go/check.sh` stops a TS edit from reusing a cached parity pass. Shown by: PR #1240, which compares the generated Go catalog against `src/mcp.ts`.
- **S-2921** (7 +1s): for a one-line PR, fetch `refs/pull/N` into your existing worktree and read the files at the PR's sha with `git show SHA:path` or `git grep SHA`. No scratch clone is needed. Shown by: #929, reviewed in a few calls.
